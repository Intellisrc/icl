Package: com.intellisrc.web.service

[Groovy] Class Range

    • com.intellisrc.web.service.Range 
    • @groovy.transform.CompileStatic
final class Range
extends java.lang.Object

      Parsed representation of a single HTTP Range: bytes=... request.

      Added to support HTTP 206 Partial Content for File responses (e.g. video streaming), which also makes the benign "Broken pipe" disconnects rare (browsers no longer need to abort and re-request to seek).

      Only single byte-ranges are supported. Multi-range requests (bytes=0-100,200-300) are intentionally not handled: parse returns null so the caller falls back to a full 200 response, which matches typical HTML5 <video> usage.

      Since:
      2.10.5

          Parameters:
          header - the raw Range header value (may be null)
          total - total size in bytes of the resource being served
          Returns:
          null if the header is absent or unsupported (no range -> serve full 200); a Range with isValid() == false if the syntax is malformed or the range is out of bounds, so the caller can emit 416 with Content-Range: bytes */total; otherwise a valid Range.
